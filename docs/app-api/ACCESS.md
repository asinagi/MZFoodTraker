# 인증과 접근 범위 (앱 데이터 API v1)

## 1. 두 API의 분리

| 구분 | 앱 데이터 API (이 문서) | 기존 관리 API |
| --- | --- | --- |
| 경로 | `/api/v1/*` | `/api/foods`, `/api/tracking/*`, `/api/planner/*`, `/api/execution/*`, `/api/collect` 등 |
| 서버 프로세스 | 별도 읽기 전용 서버 (`food_trends.app_api`, Mock은 `food_trends.app_mock`) | 기존 로컬 서버 (`python -m food_trends`) |
| 메서드 | GET·HEAD·OPTIONS만. 그 외 `405` | 상태 변경 POST 포함 |
| 인증 | 없음 (공개 가능한 읽기 전용 데이터만 제공) | 서버 프로세스별 관리 토큰 `X-MZ-Admin-Token` |
| DB 접근 | 읽기 전용 연결(`mode=ro`, `query_only`). 요청 처리 중 쓰기·마이그레이션·외부 API 호출 없음 | 쓰기·수집 실행 |
| 사용자 | 모바일·웹 앱 | 로컬 운영자 |

앱 API는 관리 API의 경로·동작을 바꾸지 않고, 관리 API로 요청을 넘기지도 않습니다.

## 2. 관리 토큰 금지

- B3의 관리 토큰은 로컬 개발 서버의 상태 변경을 보호하는 수단이며 **앱에 내장하거나 앱 개발자에게 배포하지 않습니다.**
- 앱 API는 관리 토큰이 필요 없고 받지도 않습니다. 요청에 `X-MZ-Admin-Token` 헤더가 있으면 처리하지 않고 `400 ADMIN_TOKEN_NOT_ACCEPTED`를 반환합니다(값은 기록·반환하지 않음). 실수로 토큰을 넣은 앱 빌드를 개발 단계에서 바로 발견하기 위한 장치입니다.
- 앱 API 응답에는 토큰·자격 증명·내부 경로·원문(캡션·기사 본문)이 들어가지 않습니다.

## 3. 제공 데이터 범위

| 제공 | 제공하지 않음 |
| --- | --- |
| 승인된 활성 음식의 ID·대표명·유형·승인 별칭·승인 관계 | 검토 대기 후보, 취소된 별칭, 검토자·감사 이력(actor, reason) |
| 출처별 확인 콘텐츠 수(집계 값), coverage, 관측 일수, 품질 요약 | 개별 콘텐츠 원문·캡션·링크·작성자, 외부 콘텐츠 ID |
| Google 트렌드 RSS 표시 검색량 문구(음식명과 같은 트렌드 검색어만) | NAVER 지수(저장 금지), YouTube 영상 통계·파생 지표(정책상 비활성) |
| 출처 정책 버전·보존 기간·수집 회차 통계 | 계정 ID, 예산·쿼터, 실행 Job·Lease 등 운영 내부 상태 |

## 4. 네트워크 접근 (현재 범위: 로컬 개발)

| 서버 | 바인딩 | 비고 |
| --- | --- | --- |
| 실제 데이터 서버 `food_trends.app_api` | **루프백 고정** (`127.0.0.1`) | 다른 기기에서 접근할 수 없습니다. 외부 공개는 §6의 별도 과제 |
| Mock 서버 `food_trends.app_mock` | 기본 `127.0.0.1`, `--host 0.0.0.0`(또는 LAN IP) 명시 시 같은 네트워크 기기 접근 가능 | 가상 데이터만 제공하므로 실기기 테스트용으로 허용 |

- **Host 검사**: `Host` 헤더가 `localhost`·`127.0.0.1`·`::1` 또는 IP 주소일 때만 응답합니다. 도메인 이름은 `403 FORBIDDEN_HOST`입니다(웹 페이지가 DNS 재바인딩으로 로컬 데이터를 읽는 것을 막음). Android 에뮬레이터의 `10.0.2.2`, LAN IP는 허용됩니다.
- **CORS**: 네이티브 앱(Flutter·Kotlin·Swift·React Native)은 CORS와 무관합니다. 브라우저 웹앱은 Mock 서버에서 모든 Origin을 허용하고(`Access-Control-Allow-Origin: *`), 실제 데이터 서버는 `--cors-origin http://localhost:3000`처럼 명시한 Origin만 허용합니다. 쿠키·인증 정보는 사용하지 않습니다(`credentials` 불필요).
- 실제 기기에서 PC의 루프백 서버를 쓰려면 Android는 `adb reverse tcp:8020 tcp:8020` 후 `http://127.0.0.1:8020`을 사용할 수 있습니다.
- 평문 HTTP입니다. Android 9+ 앱은 개발 빌드에서만 `usesCleartextTraffic`(또는 network security config의 개발 도메인 예외), iOS는 개발 빌드에서만 ATS 예외(`NSAllowsLocalNetworking`)를 사용하고 배포 빌드에는 넣지 마세요.

## 5. 앱 사용자 계정

이번 범위에서는 사용자 계정·로그인·개인화 API를 만들지 않습니다. 앱 API는 모든 사용자에게 같은 공개 집계 데이터를 돌려주며 사용자 식별 정보를 받지 않습니다.

## 6. 외부 공개 전에 필요한 별도 과제 (미구현)

아래가 해결되기 전에는 앱 API를 인터넷에 공개하지 않습니다.

1. **배포 구조**: 공개용 읽기 복제본(운영 DB와 분리)이나 사전 계산 집계를 두고, 앱 API 서버를 관리 서버와 다른 호스트·계정으로 운영. 쓰기 권한 없는 DB 계정 사용(Oracle 전환 시 읽기 전용 사용자·`SET TRANSACTION READ ONLY`).
2. **전송 보안**: TLS 종단(리버스 프록시), HSTS, 평문 포트 차단.
3. **클라이언트 인증·남용 방지**: 앱 식별용 API 키 또는 App Attest/Play Integrity 같은 앱 무결성 증명, IP·키별 속도 제한, 요청 크기·시간 제한, 캐시(CDN)와 `ETag`.
4. **데이터 재배포 권한**: Instagram 관측 집계·Google 트렌드 표시값의 공개 앱 재배포·보존 조건을 출처 약관으로 확인(통합 감사에서 장기 파생 데이터 보존 권한은 미확인). 확인 전에는 Instagram 집계를 공개 응답에서 제외할 수 있도록 출처별 공개 스위치 필요.
5. **운영 관측성**: 접근 로그 보존 기간, 개인정보 최소화(IP 마스킹), 장애 알림.
6. **사용자 계정이 필요해질 경우**: OAuth 2.0/OIDC 기반 별도 인증 서버, 앱 API는 토큰 검증만 수행. 관리 API와 인증 체계 공유 금지.
